# 已知限制与待验证项

本文件描述 0.3.2 的适用边界与当前限制。

- 适用于已研究的特定 OneOS Binder 契约；普通手机缺少这些服务，不能验证仪表接入。系统权限策略可能直接拒绝绑定或 addService。
- 服务表替换影响共享媒体引用；非 USB 方法透传不等于全系统无副作用。客户端缓存旧 Binder 时可能不立即使用代理。
- 自动恢复和独立守护是尽力机制，整包 force-stop、断电、系统服务异常不保证恢复。监听器重新登记失败只记录日志。原音源、歌曲、进度不属于恢复保证。
- 恢复/卸载过程中绑定守护失败的部分路径没有完整超时反馈，可能需要用户查看日志。系统可能没有可处理卸载 Intent 的界面。
- 回调/查询位于不同 Binder 与工作线程，且服务连接与销毁存在生命周期竞态；原型未完成压力和并发测试。不能用于生产常驻。
- D1/D2 是 Binder 调用返回日志，不证明页面接受参数、图片加载或界面显示成功。
- 初始回调 appSource 为 1，随后按原服务真实值同步；若固件返回 UNKNOWN，仍可能被原界面过滤。
- 列表 typed Bitmap 增加 Binder 数据量；只验证固定五首 96×96 图片，不应直接扩到大队列大图。
- JSON/PFD 分支依赖图片路径可读；Android 9 上接收包权限仍需确认。未来 Android 的存储规则不能类推。
- 部分中控 PLAY_* 字符串命令仅记录。标准通知/MediaSession 没有接入本原型；不能据此推断所有播放器可提供完整队列。
- 诊断文件导出使用 Support.logs，当前实现只保留读取文本的末约 60000 字符，UI 虽写“完整日志”，不是无限历史归档。日志可能含原 USB 歌名、文件路径和系统版本；反馈前自行审阅。
- 原始数据、播放器音频焦点、MIDI 合成和媒体显示是不同链路，一条成功不能证明其他链路成功。
